# Spike: keyless winding at right angles (workstream A)

This tests whether right-angle gearing graded by exact kinematics opens a gap. In CAD-bench, code-running
agents averaged 4 % on a right-angle gearbox while 97 % of their attempts built (see
`../RESEARCH_GAPS.md`). This is B's proposal 3 (a winding stem at right angles), built as a separate
spike. Nothing here changes B's task.

## The task

- **Frozen movement:** B's reference stage 1 (`solution/reference_watch.py`), exported to STL by
  `build_frozen.py`, with the main plate bored at the barrel axis. A supplied square on the barrel
  arbor sits under the main plate.
- **What the agent designs:** the winding works on the underside. That is a stem along x (a stated line, coming in
  through the case wall), a wheel that turns the motion through 90 degrees (a crown/contrate wheel
  or bevel pair), any intermediate wheels, a ratchet wheel on the square, and the fixed bridges and
  posts.
- **What the agent submits:** binary STL parts (STL, not STEP, in this spike) and `winding.json`
  (mobiles with general axes, fixed parts, meshes with tooth counts and a stated sense).
- **What the brief states:** every rule and number (`build_task.py` writes it from `constants.py`).
  Only the grader's verdicts are hidden.

## The grader (`grade.py`)

The grader is a general-axis kinematic engine on manifold3d. It runs with `python -I`, opens only named files, never runs
submitted code and writes reward 0 first.

- **Hard requirements:** files, and nothing overlapping the frozen movement at rest.
- **Weighted checks (12 in total):** drive 3, direction 1, ratio 1, clear 2, held 2, seated 1, anchored 1, bounds 1.
- **How a mesh is tested:** it is sampled through one full turn of its slower wheel, at 6 samples per driver
  tooth. At every sample the overlap must be at most 0.002 mm³. Turning the driven wheel back by 3 % of its tooth pitch must then
  give at least 0.0002 mm³ of contact. A 10 % thinned tooth gives zero contact, and a wrong tooth count drifts out of mesh.
- **Speed:** grading the reference takes about 4 s.

## Reference (`reference.py`, `gears.py`)

- **Gears:** a 12-tooth involute stem pinion (module 0.15) drives a 36-tooth face gear, generated by
  envelope cutting with the pinion. A 12-tooth spur pinion (module 0.2) on the same crown wheel then drives a
  36-tooth ratchet, giving 9 stem turns per arbor turn.
- **Supports:** the crown wheel turns on a post hanging from the main plate, and the stem runs in a
  bridge between two collars.
- **Score:** 1.0.

## Reproduce

```
python3 solution/reference_watch.py REF                      # B's reference, from the repo root
python build_frozen.py REF/stage1 data                       # frozen movement STLs (committed in data/)
python reference.py SUB && python -I grade.py SUB data --reward r.txt --details d.json
python anchors.py WORK                                       # every anchor, exit 0 when all ok
python build_task.py TASK --agent opencode --oracle-submission SUB   # Harbor task
```

## Known spec weakness (found by Mikael in the viewer, 14 Nov 12:25)

GPT trial 1 passes with a design that is valid kinematically but not how a watch winds:

- **No click.** Its "ratchet" is one 108-tooth face gear on the barrel arbor, with no saw teeth on the rim
  and no click. In a real watch the mainspring would unwind back through the stem and turn the crown
  backwards. **This spec never asked for a click, so this is our omission, not the agent's.**
- **One giant face gear instead of a crown wheel plus ratchet wheel.** Real keyless works split the job
  (stem pinion to a small crown wheel, then the ratchet wheel), partly because the ratchet rim must carry
  the click teeth.
- **The stem spans under the whole wheel.** In a real movement it ends in the keyless area near the edge.

The grader checks meshing, ratio, direction, clearance and support, and the agent found the simplest shape
that satisfies exactly that. `spikes/keyless/` supersedes this spike: it requires the click (turning
backward must leave the barrel still), Breguet teeth that slip one way, and the pulled-crown setting
mode, all checked by contact simulation. A single face gear with no click cannot pass there.

To see it: `python tools/viewer/export_axes.py SUBMISSION OUT.html --frozen spikes/right_angle/data/frozen`.
